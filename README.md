# 자취방 꾸미기 에이전트

고려대 세종캠퍼스 주변 자취생을 위한 모바일 대응 웹 서비스입니다. 취향과 예산을 알려 주면 에이전트가 가구·소품 후보를 점수 순으로 보여 주고, 사용자가 직접 담아 예산을 맞춘 뒤 **내 방 사진 위에 올려 볼 수 있습니다.** (비즈니스 에이전트 설계 Project 1)

## 목적과 사용자

풀옵션 원룸에 살지만 인테리어 경험이 없고 예산이 한정된 자취생이 "무엇을 얼마에 사야 하는지" 막막한 문제를 다룹니다. 추천에는 고른 분위기, "아쉬운 점", 직접 쓴 고민, 방 크기, 예산을 씁니다. 퇴실 때 원상복구가 걱정되면 "벽에 못을 박기 어려워요" 조건으로 벽걸이 상품을 뺍니다(몇 개를 왜 뺐는지 설명).

## 실행 방법

정적 파일이라 빌드가 필요 없습니다. 데이터를 `fetch`로 읽으므로 웹 서버로 여세요.

```bash
python3 -m http.server 8765   # http://localhost:8765/index.html
python3 tools/validate_data.py
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc tools/test_agent.js
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc tools/eval_text.js
```

1. **방 정보**: 사진, 방 크기, 예산, 이미 있는 가구(모두 선택)
2. **취향**: 방 분위기 사진(오늘의집 스타일 8개) 고르기, 아쉬운 점, 조건, 카드에 없는 고민 직접 쓰기
3. **추천 상품 고르기**: 카테고리별 후보 담기, 합계와 예산 확인, "예산에 맞춰 자동 선택"
4. **내 방에 올려 보기**: 사진 위에서 끌어 옮기고 핸들로 크기·회전·삭제, PNG 저장

## 핵심 파일 (5개)

| 파일 | 역할 |
|---|---|
| `agent/agent.js` | 글·사진 해석, 취향 진단, 점수화, 방 크기 반영, 후보 목록, 예산 안 자동 선택, 판단 기록 |

## 데이터와 출처

상품은 공개 데이터셋 **Amazon Berkeley Objects(CC BY 4.0, Amazon.com)** 에서 가져왔고 이미지는 흰 배경을 지운 투명 WebP입니다. **ABO에는 가격이 없어 가격은 추정값**이며 화면에 그렇게 표시합니다. 방 분위기 사진 8장은 **Pexels**(Pexels License) 사진이고 작가는 화면과 `data/moods.json`에 있습니다. 만든 스크립트는 `tools/abo_*.py`입니다.

## 작업 과정

1. 공고의 배점을 보고 범위를 줄였습니다. 평면도, 이미지 생성 AI, Claude API는 빼고 "사진 위에 상품 올려 보기"로 정했습니다.
2. 직접 그린 SVG 가구 23개로 시작했고, 3D 스캔 뷰어와 영상 프레임 캡처는 시도 후 되돌렸습니다.
3. 교수님 피드백(실제 가구 데이터)을 반영해 쇼핑몰 크롤링 대신 ABO에서 후보 166개를 걸러 번역하고 배경을 지워 153개를 썼습니다.
4. 에이전트를 먼저 만들어 테스트한 뒤 화면을 붙였고, 써 보며 문구와 흐름을 고쳤습니다.

**글 해석 평가**(`eval_text.js`): 문장과 정답은 제가 직접 썼고 규칙도 제가 쓰므로 **독립된 평가가 아닙니다.** 정답(카테고리·조건·취향) 대비 F1입니다.

| 문장 세트 | 기존 규칙 | 규칙 보강 | +유사도 | +되묻기* |
|---|---|---|---|---|
| 신규 42문장(규칙 확정 후 작성, **조정 전**) | 59% | 70% | 71% | 73% |
| 키워드 없는 돌려 말하기 24문장(**조정 전**) | 0% | 9% | 9% | 28% |

*사용자가 알맞은 후보를 고른다고 가정한 상한선. 신규 세트의 "조정 전" 값은 당시 실행 기록이며, 그 문장을 보고 규칙을 고친 뒤인 지금의 `eval_text.js`는 97~100%가 나오지만 **의미가 없어** 쓰지 않았습니다(검증용 세트도 규칙을 쓸 때 문장을 봐서 제외). 돌려 말하기 세트는 아직 조정하지 않아 그대로 재현됩니다.

## 효과적이었던 방법 3가지

1. **공고의 배점을 먼저 보고 범위를 줄였습니다.** 시간이 많이 드는 3D 스캔은 시도 후 접었습니다.
2. **로직을 화면에서 분리해 먼저 테스트했습니다.** `agent.js`는 DOM에 의존하지 않아 화면 없이 예산·엣지 케이스를 검증했습니다.
3. **자동 점수를 의심하고 직접 확인했습니다.** 배경 제거는 컨택트 시트로 봐서 불량을 찾았고, 글 해석 평가는 **100%가 나온 것을 이상하게 여겨** 문장 누수를 발견하고 새 문장 세트로 다시 쟀습니다.

## 어려웠던 점 3가지

1. **실제 가구 데이터 확보.** 쇼핑몰은 API가 없고 크롤링은 약관 문제가 있었습니다. → 공개 데이터셋 ABO. *남은 문제: 가격은 추정값.*
2. **이미지 품질.** 흰 상품이 배경에 지워지고 가구 안쪽 흰 구멍이 남았습니다. → 갇힌 영역 제거, 불량 13개 제외. *남은 문제: 롤 이불 밑 흰 띠.*
3. **자유 문장 이해.** 규칙 보강으로 59%→70%는 올렸지만, **글자 유사도는 돌려 말하기를 거의 못 잡았습니다**(9%). → 애매하면 "이런 뜻인가요?" 되묻고, 못 알아들은 표현과 상품이 없는 요청은 숨기지 않고 알립니다. *남은 문제: 진짜 의미 이해는 LLM이나 임베딩이 필요합니다.*

## 알려진 한계

- **직접 쓴 글은 LLM이 아니라 규칙과 글자 유사도로 해석**해서 돌려 말하기에 약합니다. 앞의 표가 근거입니다.
- 오늘의집 스타일 8개를 우리 취향 4가지(미니멀·모던·우드·따뜻한)로 **근사 환산**했고, 상품의 스타일은 상품명 키워드로 자동 분류해 부정확할 수 있습니다. 사진 속 가구와 상품은 연결되어 있지 않습니다.
- 방 크기는 "바닥의 절반까지 가구를 둘 수 있다"고 가정하고, 보유 가구 크기는 일반적인 값입니다. 사진 합성에는 원근감이 없습니다.
- 러그·소품은 후보가 적고, 커튼·빈백은 상품이 없어 빠졌습니다. 상품은 아마존 미국 상품입니다.
- 실제 폰 터치, 실제 방 사진, PNG 저장은 직접 검증하지 못했고 배포는 하지 않았습니다.
