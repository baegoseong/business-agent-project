# 자취방 꾸미기 에이전트

고려대 세종캠퍼스 주변에서 자취하는 대학생을 위한 모바일 대응 웹 서비스입니다. 예산과 취향을 입력하면 에이전트가 부족한 가구·소품을 골라 주고, 내 방 사진 위에 직접 올려 볼 수 있습니다. (비즈니스 에이전트 설계 Project 1)

## 목적과 사용자

풀옵션 원룸에 살지만 인테리어 경험이 없고 예산도 한정된 자취생이 "무엇을 얼마에 사야 하는지" 막막해하는 문제를 다룹니다. 전문 컨설팅 없이 예산 안에서 구성을 정하고, 못을 박지 않는 제품 위주로 추천해 퇴실 때 원상복구 부담도 줄입니다.

## 실행 방법

빌드 도구 없이 정적 파일만으로 동작합니다. 가구 데이터를 `fetch`로 읽기 때문에 파일을 직접 열지 말고 웹 서버로 여세요.

```bash
python3 -m http.server 8765
# 브라우저에서 http://localhost:8765/index.html
```

1. **방 정보**: 방 사진(선택), 예산, 이미 있는 가구를 입력합니다.
2. **취향**: 분위기와 색감, 아쉬운 점을 고릅니다.
3. **추천**: 에이전트가 구성과 이유, 판단 과정을 보여 줍니다.
4. **배치**: 추천 가구를 사진 위에 올려 끌어 옮기고, 크기·회전을 조절하고, 모서리의 ✕로 삭제하고, PNG로 저장합니다.

검증은 아래 명령으로 다시 실행할 수 있습니다. 두 번째는 macOS 기본 JavaScriptCore를 쓰므로 Node가 필요 없습니다.

```bash
python3 tools/validate_data.py
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc tools/test_agent.js
```

## 핵심 파일 (5개)

| 파일 | 역할 |
|---|---|
| `agent/agent.js` | 취향 진단, 점수화, 예산 안 선택, 초과 시 대체·제외, 판단 기록 |
| `overlay.js` | 사진 위 가구 배치 (Canvas, 드래그, 크기·회전, 삭제, 저장) |
| `app.js` | 4단계 화면 흐름과 에이전트·배치 연결 |
| `data/items.json` | 가구 대표 유형 23개 (가격, 치수, 스타일, 대체 관계) |
| `tools/test_agent.js` | 에이전트 로직 테스트 |

## 작업 과정

1. 과제 공고를 읽고 범위를 줄였습니다. 평면도 배치, 이미지 생성 AI, 웹 AR, Claude API 호출은 비용·키 관리·결과 불안정 때문에 빼고, "사진 위에 가구 이미지를 올려 보기"로 정했습니다.
2. 교수님 피드백(가구 데이터 수집이 어렵다)을 반영해 실제 상품을 긁어오지 않고 **대표 유형 23개**를 직접 정의했습니다. 가격·치수는 시중 제품을 참고한 추정값이고, 이미지는 직접 그린 SVG입니다.
3. 화면보다 에이전트 로직을 먼저 만들고 테스트했습니다. 그 뒤 4단계 화면을 붙였습니다.
4. 단계마다 커밋해 이력을 남겼습니다.

에이전트의 판단 흐름은 다음과 같습니다. 선택지에서 스타일 점수를 계산해 취향을 진단하고, 가구마다 우선순위·스타일 일치·아쉬운 점을 합산해 점수를 매깁니다. 같은 물건의 비싼/싼 버전은 한 계열로 묶어 하나만 올립니다. 점수 순으로 예산에 맞으면 담고, 모자라면 같은 계열의 더 저렴한 대체품으로 바꾸거나 제외하며, 그 이유를 화면에 보여 줍니다.

## 효과적이었던 방법 3가지

1. **공고를 먼저 읽고 범위를 줄였습니다.** 배점이 결과물보다 과정·검증·성찰에 쏠려 있음을 확인하고, 시간이 많이 드는 기능을 과감히 뺐습니다.
2. **로직을 화면에서 분리해 먼저 테스트했습니다.** `agent.js`가 DOM에 의존하지 않아 화면 없이 대표·엣지 케이스를 바로 검증할 수 있었습니다.
3. **데이터 검증 스크립트로 사람 실수를 잡았습니다.** 손으로 쓴 JSON의 논리 오류를 코드가 먼저 찾아 줬습니다.

## 어려웠던 점 3가지

1. **가구 데이터 수집.** 쇼핑몰에는 공개 API가 없고 크롤링은 약관 문제가 있습니다. → 대표 유형을 직접 정의하는 방식으로 우회했습니다. *남은 문제: 가격은 추정값입니다.*
2. **개발 환경 제약.** 이 컴퓨터에 Node가 없었고 화면을 직접 눈으로 보기 어려웠습니다. → 기본 내장된 JavaScriptCore로 테스트하고 헤드리스 Chrome 스크린샷으로 화면을 확인했습니다. *남은 문제: 실제 손가락 터치는 검증하지 못했습니다.*
3. **예산이 빠듯할 때의 선택.** 점수가 높은 항목부터 담는 방식이라, 8만 원에서 필수에 가까운 이불 커버가 제외되고 다른 항목이 먼저 들어갔습니다. *남은 문제: 필수 항목을 먼저 확보하도록 선택 순서를 바꿔야 합니다.*

## 알려진 한계

- 가구는 대표 유형 23개이며 실제 상품·재고·가격과 연동되지 않습니다. 가격과 치수는 추정값입니다.
- 사진 합성은 원근감을 반영하지 않습니다. 방 너비를 약 3.2m로 가정해 크기를 맞추고, 러그·침구는 세로를 눌러 바닥에 깔린 느낌만 냅니다.
- 실제 폰에서의 터치 조작, 큰 사진 업로드, 이미지 저장은 직접 검증하지 않았습니다.
- 방 구조(도면)는 인식하지 않고, 배치 규칙 검증(동선, 문 앞 비우기)은 구현하지 않았습니다.
- 확장 과제: 이미지 생성 AI로 꾸며진 모습 생성, 웹 AR, 쇼핑몰 연동, 필수 항목 우선 확보.
