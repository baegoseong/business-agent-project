# 자취방 꾸미기 에이전트

고려대 세종캠퍼스 주변에서 자취하는 대학생을 위한 모바일 대응 웹 서비스입니다. 취향과 예산을 알려 주면 에이전트가 방에 어울리는 가구·소품 후보를 점수 순으로 보여 주고, 사용자가 직접 담아 예산을 맞춘 뒤 **내 방 사진 위에 올려 볼 수 있습니다.** 

## 목적과 사용자

풀옵션 원룸에 살지만 인테리어 경험이 없고 예산이 한정된 자취생이 "무엇을 얼마에 사야 하는지" 막막한 문제를 다룹니다. 추천에는 고르신 스타일과 "아쉬운 점"에 대한 답변을 쓰고, 퇴실 때의 원상복구를 고려해 **못 없이 설치할 수 있는 상품에 가점**을 주며, 벽에 못이 필요한 상품에는 주의 문구를 붙입니다.

## 실행 방법

빌드 도구 없이 정적 파일로 동작합니다. 가구 데이터를 `fetch`로 읽기 때문에 파일을 직접 열지 말고 웹 서버로 여세요.

```bash
python3 -m http.server 8765
# 브라우저에서 http://localhost:8765/index.html
```

1. **방 정보**: 방 사진(선택), 예산, 이미 있는 가구
2. **취향**: 분위기, 색감, 아쉬운 점
3. **추천 상품 고르기**: 카테고리별 1순위와 "같은 종류 다른 상품"을 보고 담기, 합계와 예산 확인. "예산에 맞춰 자동 선택" 버튼도 있음
4. **내 방에 올려 보기**: 담은 상품을 사진 위에서 끌어 옮기고, 크기·회전 조절, ✕로 삭제, PNG 저장

검증 명령 (두 번째는 macOS 기본 JavaScriptCore를 쓰므로 Node가 필요 없습니다):

```bash
python3 tools/validate_data.py
/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc tools/test_agent.js
```

## 핵심 파일 (5개)

| 파일 | 역할 |
|---|---|
| `agent/agent.js` | 취향 진단, 점수화, 후보 목록(`suggest`), 예산 안 자동 선택(`recommend`), 판단 기록 |
| `app.js` | 4단계 화면 흐름, 담기와 예산 계산 |
| `overlay.js` | 사진 위 가구 배치 (Canvas, 드래그, 크기·회전, 삭제, 저장) |
| `data/items.json` | 상품 153개, 22개 카테고리 |
| `tools/test_agent.js` | 에이전트 로직 테스트 |

## 데이터와 출처

상품 정보와 이미지는 공개 데이터셋 **Amazon Berkeley Objects(ABO), CC BY 4.0, Amazon.com** 을 사용했습니다(ABO 논문, CVPR 2022). 이미지는 흰 배경을 지운 투명 WebP(`assets/products/`)입니다. **ABO에는 가격이 없어서 가격은 카테고리 기준가와 크기·키워드로 추정한 값**이며 화면에도 "참고용 추정값"으로 표시합니다. 상품명은 직접 번역했습니다. 데이터를 만든 스크립트는 `tools/abo_*.py`입니다.

## 작업 과정

1. 과제 공고를 읽고 범위를 줄였습니다. 평면도 배치, 이미지 생성 AI, Claude API 호출은 비용과 키 관리, 결과의 불안정 때문에 빼고 "사진 위에 상품 이미지 올려 보기"로 정했습니다.
2. 처음에는 가구 이미지를 직접 SVG로 그려 23개로 시작했습니다. 이후 방 **3D 스캔 뷰어**와 **영상 프레임 캡처**를 시도했으나 범위가 커서 되돌렸습니다.
3. 교수님 피드백(실제 가구 데이터 수집이 어렵다)을 반영해 실제 상품으로 바꾸기로 했습니다. 쇼핑몰 크롤링은 약관 문제가 있고 직접 입력은 부담이 커서 공개 데이터셋 ABO로 정했습니다.
4. ABO 메타데이터에서 자취방에 맞는 후보 166개를 걸러 한글로 번역하고, 원본 이미지를 받아 배경을 지웠습니다. 결과를 눈으로 보고 13개를 제외해 153개를 사용합니다.
5. 에이전트를 만들고 테스트한 뒤 화면을 붙였습니다. 직접 써 보며 나온 의견으로 추천 문구와 3단계(직접 고르기)를 고쳤습니다. 단계마다 커밋했습니다.

- **데이터 검증** (`validate_data.py`): 153개의 필드, 값 범위, 이미지 존재와 비율, "저가 대체는 같은 카테고리에서 더 저렴한가", 가격이 추정 표시인지, 출처를 검사합니다. 직접 그린 데이터 단계에서 처음 돌렸을 때 제가 대체 관계를 반대로 적은 2건을 실제로 잡았습니다.

## 효과적이었던 방법 3가지

1. **공고의 배점을 먼저 보고 범위를 줄였습니다.** 결과물보다 과정·검증·성찰에 점수가 쏠려 있어서, 3D 스캔처럼 시간이 많이 드는 기능은 시도해 보고 과감히 접었습니다.
2. **로직을 화면에서 분리해 먼저 테스트했습니다.** `agent.js`가 DOM에 의존하지 않아 화면 없이 예산·엣지 케이스를 바로 검증했고, Node 없이 macOS 내장 JavaScriptCore를 썼습니다.
3. **자동 판정만 믿지 않고 결과를 눈으로 확인했습니다.** 배경 제거 결과를 컨택트 시트로 보니 자동 표시가 놓친 불량(안내 문구 사진, 가구 안쪽 흰 구멍, 90° 뒤집힌 거울 크기)이 나왔고 고치거나 제외했습니다.

## 어려웠던 점 3가지

1. **실제 가구 데이터 확보.** 쇼핑몰은 공개 API가 없고 크롤링은 약관 문제가 있으며 직접 입력은 너무 힘들었습니다. → 공개 데이터셋 ABO로 해결했습니다. *남은 문제: 가격이 없어 추정값이고, 아마존 미국 상품이라 한국 쇼핑몰 링크가 없습니다.*
2. **이미지 품질.** 흰 상품이 흰 배경에 지워지고, 투명 상품이 사라지고, 가구 안쪽의 갇힌 흰 배경이 남았습니다. → 갇힌 영역 제거와 불량 13개 제외로 대응했습니다. *남은 문제: 롤 이불 밑 흰 띠, 거울 유리가 불투명한 점.*
3. **에이전트의 예산 배분.** 처음에는 점수 높은 순으로 담아 15만 원에 책장 2개로 예산을 다 썼고, 수납 고민 하나가 추천을 독점했습니다. → 예산 45% 규칙, 고민당 2개 상한과 남은 예산 보충을 넣었습니다. *남은 문제: 같은 카테고리의 저가 대체가 다른 종류의 상품이 될 수 있습니다(책장 → 걸이형 선반 정리함).*

## 알려진 한계

- 가격은 실제 판매가가 아닌 **추정값**이고, 스타일 분류는 상품명의 키워드로 자동 판정했습니다.
- 상품은 아마존 미국 상품이며, 러그(2개)·소품(1개)은 후보가 적고 커튼·빈백은 쓸 만한 후보가 없어 빠졌습니다.
- 사진 합성은 원근감을 반영하지 않습니다. 사진 속 방 너비를 약 3.2m로 가정해 크기를 맞추며, 치수는 ABO 데이터를 사진 비율에 맞춰 보정한 근사값입니다.
- 실제 손가락 터치, 실제 방 사진, "PNG 저장"은 직접 검증하지 못했습니다. 배포는 아직 하지 않았습니다.
- 확장 과제: 이미지 생성 AI나 웹 AR로 꾸며진 모습 보기, 쇼핑몰 연동, 필수 항목 우선 확보.
